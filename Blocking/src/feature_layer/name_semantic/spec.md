# Name Semantic Feature Spec (Dim 7)

## 1. Specifications & Schemas
**Inputs:**
- `emb_a` (NumPy Array 1D): The pre-computed FAISS embedding vector for Entity A.
- `emb_b` (NumPy Array 1D): The pre-computed FAISS embedding vector for Entity B.

**Outputs:**
- `dim_7_semantic_cosine` (Float): [0.0, 1.0]

## 2. Requirements (Business Logic)
- **Dim 7:** Semantic Cosine Similarity.
  - Assert both inputs are 1D arrays of the same shape: `assert emb_a.ndim == 1 and emb_b.ndim == 1` and `assert emb_a.shape == emb_b.shape`.
  - Calculate the dot product between `emb_a` and `emb_b`.
  - Clamp both lower and upper bounds to guarantee strict `[0.0, 1.0]` range: `min(1.0, max(0.0, dot_product))`.

## 3. Assumptions
- Both `emb_a` and `emb_b` are generated by an embedding model (e.g., MiniLM) on the `name_for_faiss` strings.
- Both vectors **must be L2-normalized** before this function receives them, otherwise the dot product is not equivalent to cosine similarity.

## 4. Edge-Cases & Errors
- **Missing Embeddings (Fail-Fast):** If either embedding is `None`, the module must crash loudly to prevent silent poisoning of the ML model. Implement an explicit check: `if emb_a is None or emb_b is None: raise ValueError("Semantic embeddings cannot be None. Upstream leakage detected.")`.
- **Floating-Point Inaccuracy:** Float32 rounding errors natively cause `L2-normalized` dot products to slightly exceed `1.0`. Upper-bound clamping (`min(1.0, score)`) prevents this mathematical anomaly.
- **Negative Values:** Clamping the lower bound (`max(0.0, score)`) ensures strict `[0, 1]` bounding for XGBoost monotonic constraints.
- **Dimensionality Mismatch:** By asserting `emb_a.shape == emb_b.shape` instead of hardcoding `384`, the feature layer remains decoupled from specific embedding models and immune to unequal vector crashes.
